# Project structure

This describes two things: the layout of an app generated by `serixa new`, and the layout of the SERIXA framework itself. Most readers only need the first section.

## A generated application

```text
blog/
  public/
    index.php               # front controller — your app's entry point
    app.css                  # your app's stylesheet
    assets/
      runtime/
        serixa.js            # copy of the framework's PE runtime script
  pages/
    HomePage.php             # App\Pages\HomePage — one class per page
  components/
    ArticleCard.php          # App\Components\* — reusable widgets you compose
  layouts/
    AppLayout.php            # App\Layouts\* — shared chrome (assets + shell)
  themes/
    DarkTheme.php            # App\Themes\* — optional, via make:theme
  plugins/
    ChartsPlugin.php         # App\Plugins\* — optional, via make:plugin
  config/
    app.php                  # plain PHP array: name, preset, title
  resources/                 # optional source assets (pre-build CSS, etc.)
  composer.json              # requires serixa/framework via a path or version constraint
  README.md                  # generated quick-reference for this app
```

### What lives where

| Path | Purpose | Namespace |
|------|---------|-----------|
| `public/` | Everything the web server serves directly. Front controller + static assets. | — |
| `pages/` | One class per page, each with a static `document(): Document` method. | `App\Pages\` |
| `components/` | App-specific reusable widgets (your own composition of SERIXA widgets). | `App\Components\` |
| `layouts/` | Shared chrome: asset registration (`wrap()`) and shell composition (`shell()`). | `App\Layouts\` |
| `themes/` | Optional custom themes, if you don't want the default Tailwind class maps. | `App\Themes\` |
| `plugins/` | Optional CLI or runtime plugins registered via `Serixa\Console\Plugin`. | `App\Plugins\` |
| `config/app.php` | Plain PHP array (`name`, `preset`, `title`). Not a framework config loader — read it yourself if you need it. | — |

None of this is enforced by the framework at runtime. It's a convention the CLI generates for you; you can rename or reorganize folders as long as your Composer autoload map and `use` statements agree.

### Pages are plain classes

There's no `Page` base class. A page is any class with a method that returns a `Serixa\Document\Document`:

```php
final class HomePage
{
    public static function document(): Document
    {
        return Document::make()->title('Home')->body(/* widgets */);
    }
}
```

Your front controller (`public/index.php`) calls that method and renders the result.

### Layouts have two jobs

By convention, a layout class has:

- `wrap(Document $document): Document` — registers assets (CSS/JS, `ClientRuntime`) on a document, right before render.
- `shell(string $active, WidgetInterface $content): WidgetInterface` — wraps page content in `Scaffold` (or similar) chrome, and knows which nav item is active.

Nothing in the framework requires these two exact method names — it's the pattern the CLI templates and this documentation use consistently.

## The SERIXA framework itself

If you're contributing to SERIXA (not just building an app with it), this is the top-level layout:

```text
src/
  Accessibility/    ARIA helpers
  Component/        Concrete widgets (Button, Card, Scaffold, ...) + Component/Widget BC alias
  Console/          CLI application, commands, scaffolding template engine
  Contracts/        Interfaces (WidgetInterface, ThemeInterface, DocumentInterface, ...)
  Document/         Document, Head/Body, SEO manager, asset manager
  Event/            Event contracts for DOM event metadata
  Exception/        SERIXA exception hierarchy
  Inspector/        DevTools contracts + snapshots
  Performance/       Profiler contracts
  Pipeline/          Render pipeline + passes (build tree, lifecycle, theme resolution, render)
  Plugin/            Plugin contracts + manager (widgets, themes, runtime)
  Registry/          Widget registry + metadata catalog
  Rendering/         Renderer, HtmlWriter
  Runtime/           WidgetContext, RenderContext, ClientRuntime
  State/             Memory-only state engine
  Support/           Escaper, attribute builder, class merger
  Theme/             DefaultTheme (Tailwind class maps), ThemeManager
  Token/             Design tokens (color, spacing, radius, shadow, typography)
  Tree/              WidgetTree, TreeNode, TreeWalker, lifecycle visitor
  Widget/            Widget base class, factory, collection
tests/               PHPUnit suite mirroring src/
docs/                Subsystem docs + this beginner path
examples/            Runnable php examples/*.php scripts
bin/                 serixa CLI entry point
templates/           Filesystem stubs used by serixa new / make:*
assets/runtime/      serixa.js — the shipped client runtime script
validation/          Full sample apps (blog, admin-dashboard, crm) used to validate the framework
playground/          Manual demo app for exploring widgets in a browser
```

See [architecture.md](architecture.md) for how these pieces fit together at request time, and [NAMESPACE.md](NAMESPACE.md) for the `Serixa\` namespace policy.
